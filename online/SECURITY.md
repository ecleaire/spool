# SPOOL のセキュリティ対策

## ブラウザー

- オンラインHTMLのCSPで、ビルド時にSHA-256を確認したスクリプトだけを実行します。同じオリジンにある別ファイルも、ハッシュなしでは実行しません。インラインイベント・evalは許可しません。
- オンラインJSにはSRIを付与し、取得した内容の改変を検出します。更新時のキャッシュ衝突を避けるためURLに内容に応じたバージョンを付けます。
- 通信先は同じサイトと設定済みSupabaseプロジェクトのみ。画像は同じサイト、埋め込み画像、Blobに限定し、プラグイン・iframe・worker・baseタグによるURL変更を禁止します。
- 外部リンクへリファラーを送信しません。外部ページへのリンクには既存のnoopener/noreferrerを維持します。
- 接続先は公開されたconfig.jsonを優先し、ブラウザー保存の設定では差し替えません。正常な公開設定がある場合、接続設定の変更UIも表示しません。
- ログインはGoogle OAuth＋PKCE。セッションはタブのsessionStorageにSPOOL専用キーで保存します。旧保存キーは削除するため、更新後は一度再ログインが必要になる場合があります。
- iframe内ではオンライン認証を開始しません。エラー詳細のキー・JWT・Bearer値を伏せます。
- 登録名などはHTMLとして扱わず、エスケープします。画像取り込みは許可した画像形式のBase64だけを受け付けます。

## データと公開

- データへの権限はSupabaseの招待・所属・RLS/RPCで判定します。画面を隠すことを認可の代わりにしません。添付は非公開Storageを維持します。
- 匿名、未招待、別ライブラリ、閲覧者、編集者、所有者、共有解除と保存競合のSQLテストを維持します。
- 配信はout内の固定5ファイルのみ。予期しないファイルや出力先のシンボリックリンクを検出した場合はビルドを停止します。
- 公開設定を検証し、secret/service_roleキーをビルドで拒否します。GitHub ActionsにはSupabase管理者キーを渡しません。
- 公式ActionsはコミットSHAで固定。公開はmainだけに制限し、権限はビルド時の読み取りと公開時のPages/OIDCに分離します。
- 依存関係はlockfileから導入し、既知のhigh/critical脆弱性をnpm auditで検出した場合は公開を停止します。
- ブラウザーテストで、不正なスクリプト・イベント・通信がCSPに拒否されること、通常の保存・添付・ログアウトが動くことを確認してから公開します。

## 残る境界

GitHub Pagesでは任意のHTTPセキュリティヘッダーを設定できません。frame-ancestorsやX-Frame-Optionsをmetaに入れても有効にならないため、そのような設定はしていません。iframe内での認証停止は追加対策であり、HTTPヘッダーによる埋め込み拒否と同等ではありません。

同じecleaire.github.io配下の別プロジェクトは同一オリジンです。SPOOL専用の保存キーやCSPは、同じオリジンの別ページで既に動いている悪意のあるコードから完全に隔離するものではありません。第三者のコードを同じオリジンで動かす場合は、SPOOL専用ドメインまたは別オリジンへ分離する必要があります。

GitHub・Google・Supabaseの管理者アカウントのMFA、復旧方法、権限見直しも別途必要です。サイトの変更だけで安全性を保証するものではありません。
