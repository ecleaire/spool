# 共有ライブラリの操作権限（3.5.0）

参加者全員の閲覧範囲は共通です。共有ライブラリの所有者が「共有」→参加者の「操作権限」から、参加者ごとに操作を制限できます。個人ライブラリの権限設定は従来どおりです。

## DB更新が必要です

既存の `selective-sharing.sql` と `library-appearance.sql` を適用済みのプロジェクトで、Supabase SQL Editorから `supabase/member-permissions.sql` を実行してください。繰り返し実行できます。アプリの公開だけではSQLは適用されません。未適用の場合は既存の所有者／編集者／閲覧者権限を維持し、設定画面にDB更新の案内を表示します。

1. SQL適用前にプロジェクトのバックアップ方針を確認します。
2. SQLを実行します。既存参加者の権限は変わりません。
3. 共有ライブラリの所有者が対象メンバーの操作権限を保存します。
4. 対象メンバーは再読み込みし、許可した操作と禁止した操作を確認します。

## 設定できる操作

| 分類 | 操作 |
| --- | --- |
| 在庫 | フィラメント追加、商品情報編集、削除、残量だけの記録 |
| 予約 | 追加、予約／印刷状態の編集、削除 |
| 添付 | ファイル追加、ファイル／添付情報削除 |
| 共有 | 自分のフィラメントを共有先へ追加・選択変更 |

「閲覧のみ」「すべて編集可」「操作を個別設定」から選べます。「商品情報編集」は残量変更も含みます。予約フォームでの添付には予約編集とファイル追加の両方が必要です。添付付き予約の削除には予約削除と添付削除の両方が必要です。JSON全体の取り込みは全データ操作を許可した参加者に限ります。

権限は画面のボタン制御に加えて、DBの保存RPC・Storage RLSで検査します。画面から隠した操作をAPIで直接送っても許可しません。DB側の制限は保存直後から適用され、既に開いている参加者の画面は再読み込みで更新されます。

所有者の権限は変更できません。メンバー招待・解除・権限変更は引き続き所有者のみです。ライブラリ名・色の変更権限（本人／共有ライブラリの所有者または参加管理者）は追加しません。自分が以前共有した原本の共有停止は、共有追加権限を外した後もできます。共有追加権限を外すだけでは既存の共有を停止しません。

残量記録のみの参加者が既存商品を使えるよう、制限中は販売リンクの自動補完を保存データへ混ぜません。既存の在庫・予約・添付を自動移行／削除しません。

## 検証

`npm --prefix online test` でDB内の直接API操作、権限昇格拒否、変更競合、非公開Storageを検証します。`node tests/online/permissions.browser.test.mjs` はモック認証で所有者の設定画面、制限された参加者の操作、320/390px表示、旧DBの案内と権限読込失敗時のロックを検証します。本番DB・実ユーザーデータを使いません。
