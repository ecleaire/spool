# 共有ライブラリの管理者と操作権限（3.6.0）

管理者は共有ライブラリごとに設定します。共有ライブラリを作ったアカウント（ホスト）が最初の管理者です。ホストは維持され、他の管理者から解除・降格できません。

その共有ライブラリの管理者は、参加者の招待・解除・操作権限の設定と、参加済みメンバーの管理者への昇格／解除を行えます。追加された管理者も別の管理者を増やせます。他のライブラリやSPOOL全体の管理権限は付与しません。管理者以外は、自分や他のメンバーの操作制限を変更できません。DBのRPC／RLSでも同じ条件を強制します。

参加者全員の閲覧範囲は共通です。管理者は全操作を利用でき、通常の参加者は「閲覧のみ」「すべて編集可」「操作を個別設定」から設定します。管理者を解除する場合は、解除後の操作権限も同じ画面で設定できます。

## DB更新が必要です

既存の `selective-sharing.sql` と `library-appearance.sql` を適用済みのプロジェクトで、Supabase SQL Editorから次の順に実行してください。

1. `supabase/member-permissions.sql`
2. `supabase/library-administrators.sql`

前者を3.5.0で適用済みなら後者だけで更新できます。どちらも繰り返し実行できます。既存の参加者を勝手に管理者にしません。既存の所有者は、そのままホスト・初期管理者として扱います。

アプリの公開だけではSQLは適用されません。未適用の場合は既存の所有者／編集者／閲覧者権限を維持し、設定画面にDB更新の案内を表示します。操作権限SQLだけが適用済みの場合、従来の権限設定は継続利用でき、管理者追加のチェックは無効です。

SQL適用後、対象の共有ライブラリを開き、「共有を管理」→参加者の「操作権限」を開きます。「共有管理者にする」で昇格できます。参加済みのアカウントを選び、確認後に保存してください。対象メンバーは再読み込みして新しい権限を取得します。

## 設定できる操作

| 分類 | 操作 |
| --- | --- |
| 在庫 | フィラメント追加、商品情報編集、削除、残量だけの記録 |
| 予約 | 追加、予約／印刷状態の編集、削除 |
| 添付 | ファイル追加、ファイル／添付情報削除 |
| 共有 | 自分のフィラメントを共有先へ追加・選択変更 |

「商品情報編集」は残量変更を含みます。予約フォームでの添付には予約編集とファイル追加の両方が必要です。添付付き予約の削除には予約削除と添付削除の両方が必要です。JSON全体の取り込みは全データ操作を許可した参加者に限ります。

制限中は、残量変更へ販売リンクの自動補完を混ぜません。自分が以前共有した原本の共有停止は、共有追加権限を外した後もできます。権限を外すだけでは既存の共有は停止しません。個人ライブラリの管理権限は本人のままです。

DB側の制限は保存直後から適用されます。開いたままの別端末の画面は再読み込みで更新されます。既存の在庫・予約・添付を自動移行／削除しません。

## 検証

`npm --prefix online test` で自己昇格の拒否、管理者からの管理者追加、他ライブラリへの権限波及の拒否、ホスト保護、操作制限、変更競合、非公開Storageを検証します。`node tests/online/permissions.browser.test.mjs` はモック認証で管理者の設定画面、通常参加者の変更不可、320/390px表示、旧DBの案内と権限読込失敗時のロックを確認します。本番DB・実ユーザーデータを使いません。

## 設定画面の復旧（3.6.1）

未保存の権限変更がある状態で閉じる／Escを押すと、破棄確認を表示します。読み込み失敗後は同じ画面から再試行でき、保存が拒否されても入力は保持します。保存成功後の画面更新だけが失敗した場合は「権限は保存されました」と表示し、保存そのものの失敗と区別します。このUI更新に追加SQLはありません。
