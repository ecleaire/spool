

### 4.3.0: 選択した印刷予約の同期

個人予約の「共有先と同期」、または印刷予約一覧の「予約の同期先」から、予約1件と共有先を選びます。既存・今後の他の予約を自動で公開する設定はありません。フィラメントの共有設定とは独立しています。

- 原本は個人ライブラリに保存し、`shared_bookings`には明示した共有先へのリンクだけを保存します。共有先からの許可された編集・印刷状態変更は原本を更新します。競合時は入力を保持し、再読み込みを案内します。
- 別画面の更新確認は約15秒間隔。未保存の変更、アップロード中、ダイアログ操作中の自動更新を避けます。
- 共有先の参加者は選んだ予約と関連ファイルを閲覧できます。編集には予約編集、添付追加・削除には対応するファイル権限も必要です。同期先追加には共有操作権限が必要です。原本所有者、または共有先の管理者が同期を停止できます。
- 同期停止は原本を保持。共有先で「予約を削除」を選ぶと原本と全同期先から削除するため二段階で確認します。予約削除だけではStorage上のファイル本体を消しません。原本側の添付管理から必要に応じて削除します。
- 個人ライブラリへのアクセスは共有しません。ファイルのRLSは共有した予約IDに限定。同期停止後の新規取得を拒否します。発行済み署名URLは有効期間（90秒）まで、取得済みファイルは端末に残ります。
- 共有先の保存・JSONバックアップには参照予約を複製しません。原本は個人側からバックアップしてください。

**DB更新が必要です。** 既存DBには、プロジェクト所有者が `supabase/upgrade-existing.sql` をSQL Editorで適用します。最新の在庫相互編集・メンバープライバシー設定も含み、既存データは保持します。既存の全更新を適用済みの場合は `supabase/booking-sharing.sql` だけでも追加できます。繰り返し適用可能です。秘密鍵をブラウザーへ置く必要はありません。未適用時は同期ダイアログにDB更新の案内を出し、保存を無効にします。ここでの検証はPGliteとモックAPIのみで、本番DBには未適用です。

ユーザー管理は「ライブラリのメンバー」と、サービス管理者だけに表示する「SPOOLの利用設定」を分けました。招待先・付与する役割を確認できます。スマホの上部ボタンは短いラベルと2段配置に統一しました。
